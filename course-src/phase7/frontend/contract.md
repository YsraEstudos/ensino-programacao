# Contrato F-31/F-32

1. `route` reconhece lista vazia/#/ e detalhe# /tasks/:id (sem o espaço ilustrativo); decodeURIComponent seguro; caminho desconhecido/malformado vira not-found. A UI mantém voltar/avançar, link profundo, título e foco no heading após navegar. Links e voltar/avançar do navegador revalidam na rota válida; alteração externa na API deve aparecer sem clicar Atualizar. Revalidação do detalhe da mesma tarefa preserva o controle, foco e escolha ainda não salva; o campo permanece interativo. Sem draft, o estado da API atualiza o campo. Salvar confirma a escolha enviada; se houver nova escolha durante o salvamento, ela permanece pendente. O skip-link move foco para main e mantém hash/rota/quadro.
2. `validateTasks` exige array com IDsstring únicos, título não vazio, status todo/doing/done e updatedAt finito; devolve cópias dos campos conhecidos e preserva texto hostil como texto. JSON inválido deve gerar TypeError, não virar lista vazia silenciosamente.
3. `createModel` recebe request(board), changed(state) e initialTasks opcional. Expõe state/load/invalidate. Cada load emite loading ou revalidating com snapshot independente do cache daquela chave, depois ready/empty/error. Erro genérico preserva cache da chave e permite retry. Resposta inválida é erro, e resposta de geração anterior nunca altera o estado/cache atual. Duas chamadas à mesma chave também seguem latest-request-wins. Invalidate remove cache. Não encaminhe detalhes internos da API ao usuário.
4. Persistência: `openDatabase(name?)` abre versão2, migra v1cards para tasks em transação de upgrade, preserva dados e transforma completed; readTasks usa readonly, writeTasks substitui snapshot em única transação e resolve no complete, rejeita erro/abort. Bloqueio de outra aba deve produzir instrução recuperável também na UI: “Feche outra aba do quadro e tente novamente.”. Depois de fechar a aba antiga e recarregar, a persistência deve retomar; feche a conexão no versionchange.
5. API fornecida: GET/api/tasks?board=all|empty|error|slow; POST/api/tasks `{title}`→201; PATCH/api/tasks/:id `{status}`→200. Seed e atraso700ms determinísticos, porta local disponível; entradas inválidas400, origem alheia403, JSONlimit4KiB, JSONmedia415. A fixture não autentica. A política do produto não permite mutações offline.
6. UI tem elementos nativos com nomes acessíveis, headings e regiões nomeadas, status aria-live, alert de falha, aria-busy, skip-link, foco visível e controles44px; layout375px sem overflow. Três colunas no desktop, uma no mobile. XSS textual permanece inerte.
7. Medir LCP/CLS/INP com biblioteca local, sem telemetria. Explique amostra incompleta e limites de laboratório. TypeScript deve verificar tipos de HTMLElement, formulários, eventos, Custom Elements e IndexedDB; não substituir validação de runtime por tipos.
8. Contratos API/modelo/manutenção, E2E de navegador, migração e regressões passam; acrescente casos relevantes para seu patch. Nenhum skip/import/timeout é aceito como sucesso. F-33 e I-F32 requerem registro antes/depois, não só uma implementação pronta.

Arquivos com TODO compõem trabalho substantivo. Componentes, servidor, testes e estilos são apoio para focar estado/concorrência/persistência. O aluno deve explicar renderização/estado/roteamento no ADR e implementar as lacunas; copiar a referência não comprova autonomia.
