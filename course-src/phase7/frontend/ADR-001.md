# ADR-001 — Web Components e estado explícito

Contexto: evolução do Kanban11.08/13.14; duas rotas, API imprevisível e dados de versões anteriores. Usuários navegam por teclado e rede pode falhar. Tecnologias: Web Components nativos; não são um framework equivalente ao React.

Decisão inicial para revisar: composição `kanban-app`/`kanban-board` em light DOM; renderização derivada de state; hash router para links profundos sem infraestrutura; modelo puro com cache por chave e geração monotônica; IndexedDBv2 com upgrade transacional; tsc para DOM e web-vitals para observação. Servidor Node fornece API deterministicamente sem conta externa. Nenhuma dependência na raiz do curso.

Alternativas: React adiciona runtime/estado/router sem ser necessário a este exercício; Shadow DOM isola estilos mas exige rever nomes/semântica/testes; History API permite URLs limpas porém exige fallback; AbortController poupa recursos mas não substitui guarda de geração (mocks/respostas já resolvidas podem ignorar abort); localStorage bloqueia thread e não fornece upgrade transacional. IndexedDB não resolve conflito remoto ou fila de mutação.

Evidência a anexar: testes de cache/mesma chave, corrida700ms no navegador, reabertura v2 preservando legado, estado de foco e ausência de overflow375px. Descreva custo de render total, observadores Web Vitals e carregamento inicial; não prometa desempenho com uma amostra.

Consequências: código sem framework requer disciplina explícita de lifecycle/cleanup. A lista é reconstruída; o painel de detalhe da mesma tarefa é mantido para preservar controle, foco e draft não salvo durante revalidação. A seleção acompanha a API somente quando não há edição pendente; o draft é encerrado após confirmação da escolha enviada ou ao deixar a rota. Uma revalidação preserva foco no heading se ele ainda estava focado; não o toma de um controle para onde o usuário já navegou. Hashchange revalida rotas válidas, inclusive histórico; skip-link foca main sem hashchange. A UI preserva a orientação de fechar outra aba no bloqueio de upgrade. Service worker cacheia apenas shell estático após primeira visita online; IndexedDB preserva dados em reload offline. Mudar versão do cache exige nova revisão de atualização/rollback. Cache é snapshot de leitura; concorrência de múltiplos escritores, autenticação, RUM, outros navegadores e auditoria WCAG ficam fora da prova automatizada. Explique quais alternativas manteria ou mudaria com evidências.
