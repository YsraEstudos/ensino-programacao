Modelo mental aprofundado
Generics preservam relacoes entre entradas e saidas. O aluno comeca com funcoes simples como
identity/getProp e so depois vai para constraints. A pergunta obrigatoria e: "qual relacao concreta o
parametro de tipo esta preservando?" Se nao houver resposta, talvez um tipo concreto seja melhor.
Overloads, union e generic resolvem problemas diferentes. Overload e util quando ha assinaturas publicas
distintas suportadas pelo mesmo runtime; union e melhor quando o corpo realmente trata um conjunto
comum; generic e melhor quando entrada e saida precisam manter relacao.
Const type parameters aparecem como recurso moderno para inferencia literal em APIs genericas. O aluno
tambem aprende que generics complexos podem aumentar tempo de typecheck e dificuldade de leitura.
Erros e concepcoes que a etapa deve revelar
• Criar generic que nao preserva relacao nenhuma.
• Usar overload quando union simples e mais honesta.
• Adicionar parametro de tipo so para parecer flexivel.
Exemplo resolvido - generic que preserva o tipo
function primeiro<T>(itens: readonly T[]): T | undefined {
  return itens[0];
}
const n = primeiro([1, 2, 3]); // number | undefined
O ponto não é “usar generic”, e sim manter uma relação: o tipo de retorno depende do tipo dos elementos
recebidos.
